# 📋 ESP - Raspberry Pi 연동 테스트 가이드
> **이미지 전송 강제 테스트 및 상태 초기화 방법**

ESP 센서 노드가 이미지를 전송하려고 할 때 **`[Early Exit] 마스터가 이미 완료한 이미지입니다.`** 로그가 나타나며 전송이 생략되는 현상은 **드론 마스터(라즈베리 파이)의 데이터 수집 최적화 프로토콜(v3.5 이상)**에 의한 정상적인 동작입니다. 

본 문서에서는 테스트 목적(전체 데이터 청크 전송 루프 검증 등)으로 이미지 전송을 처음부터 강제로 다시 수행하기 위해 **라즈베리 파이 및 센서 노드에서 어떤 데이터를 어떻게 제거해야 하는지** 상세히 설명합니다.

---

## 🔍 1. 현상 분석: 왜 전송이 생략되었을까요?

드론 마스터(`drone_master.py`)와 데이터베이스 관리자(`db_manager.py`)는 네트워크 대역폭과 센서 노드의 배터리를 절약하기 위해 **멱등성(Idempotency) 및 조기 종료(Early Exit)** 기능을 내장하고 있습니다.

### ⚙️ 동작 메커니즘
1. 센서 노드가 이미지 `6.jpg` (세션 ID: `57242dc9`)의 전송을 준비하며 **BEACON**을 전송합니다.
2. 마스터는 수신한 `s_id`와 `data_id`를 기반으로 SQLite 데이터베이스(`drone_system.db`)를 조회합니다.
3. 데이터베이스의 `image_sessions` 테이블에서 해당 세션의 `status`가 **`COMPLETED`** 상태인 것을 확인합니다.
4. 마스터는 이미 수집이 완벽히 완료된 파일로 판정하여 노드에게 즉시 **`COMPLETE_ACK`**를 전송합니다.
5. 노드는 전송 루프를 생략하고 즉시 이미지를 `sent/` 폴더로 이동시킵니다.

> [!WARNING]
> 단순히 라즈베리 파이의 `collected_images/` 디렉토리 내 물리 파일(`.jpg`)만 삭제할 경우, **데이터베이스 레코드(`COMPLETED`)가 남아 있어 조기 종료가 계속 발생**합니다. 따라서 반드시 데이터베이스 상태도 초기화해야 합니다.

---

## 🛠️ 2. 해결 방법 1: 라즈베리 파이 데이터 초기화 (추천)

라즈베리 파이에서 이전 수집 이력을 삭제하여 마스터가 해당 이미지를 완전히 새로운 데이터로 인식하게 만듭니다.

### 방법 A. 특정 이미지의 완료 상태만 제거하기 (개별 테스트용)
라즈베리 파이 터미널에서 SQLite3 CLI를 사용하여 특정 세션(`57242dc9`)의 레코드와 저장된 파일을 개별 삭제합니다.

```bash
# 1. drone-master/server_udp/pi 디렉토리로 이동
cd /path/to/drone-master/server_udp/pi

# 2. SQLite 데이터베이스에서 특정 세션 이력 제거
sqlite3 drone_system.db "DELETE FROM image_sessions WHERE s_id = 'S01' AND data_id = '57242dc9';"

# 3. 수집 폴더에서 해당 세션의 임시 파일 및 완성본 이미지 삭제
rm collected_images/S01_57242dc9.tmp
rm collected_images/S01_57242dc9.jpg
```

---

### 방법 B. 모든 수집 이력 완전 초기화 (전체 재테스트용)
모든 센서의 기록과 수집된 파일을 지우고 초기 상태로 깔끔하게 테스트하고자 할 때 사용합니다.

```bash
# 1. 실행 중인 drone_master.py 프로세스 종료 (Ctrl + C)

# 2. SQLite 데이터베이스 파일 삭제 (다음 실행 시 자동 재생성됨)
rm drone_system.db

# 3. 수집된 모든 임시 파일 및 이미지 삭제
rm -rf collected_images/*
```

## 💡 3. 해결 방법 2: 센서 노드 측에서 데이터 ID 새로 고침 (라즈베리 파이 접속 불가 시)

라즈베리 파이에 원격 접속하기 어려운 환경이라면, **센서 노드 측의 파일 상태를 변경**하여 마스터가 이를 완전히 새로운 이미지로 인식하게 강제할 수 있습니다.

### 원리
마스터가 세션을 구분하는 `data_id`는 다음과 같은 조합의 해시(CRC32) 값입니다:
$$\text{data\_id} = \text{CRC32}(\text{s\_id} + \text{"\_"} + \text{mtime(수정 시간)} + \text{"\_"} + \text{fsize(파일 크기)})$$

따라서 파일의 **수정 시간(mtime)**이나 **파일 크기(fsize)**가 1바이트라도 변경되면 `data_id`가 완전히 바뀌며, 마스터는 새로운 전송 세션으로 인식해 처음부터 청크를 요청하게 됩니다.

### 실행 방법
* **C++ ESP32/ESP8266 노드인 경우:**
  ESP 보드를 재부팅하거나 파일시스템 내의 `6.jpg`를 지우고 새로 업로드하면 내부 `millis()` 또는 업로드 시점에 따라 `mtime` 값이 갱신되어 새로운 `data_id`가 부여됩니다.
* **이미지 이름 변경:**
  `/images` 디렉토리 내에 존재하지 않는 파일명(예: `7.jpg`)을 새로 넣어 테스트를 진행합니다.
* **임의 이미지 삽입:**
  새로운 피사체를 촬영하거나 페인트 툴로 약간 편집하여 파일 용량을 미세하게 다르게 한 뒤 `/images`에 넣으면 강제로 전체 전송 과정을 검증할 수 있습니다.
