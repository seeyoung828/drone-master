# ⏱️ 데이터 수집 속도 저하 원인 분석 및 최적화 보고서

`drone_test_log.txt` 분석 결과, 단일 이미지 수집 시 발생하는 심각한 속도 저하 문제의 근본 원인과 이를 해결하기 위한 단계별 방안을 제시합니다.

---

## 1. 현상 분석 (Log Analysis)

로그상에서 다음과 같은 병목 현상이 관찰됩니다:
- **반복적인 재전송:** `[Retry] Sensor_01 GRANT 재전송 (1/3)`이 슬롯 내에서 무수히 반복됨.
- **저효율 슬롯 점유:** 5초(`SLOT_TIME_LIMIT`)를 꽉 채워 점유하지만, 실제 수집된 청크는 3~10개 내외에 불과함. (정상 환경에서는 1초 미만에 40개 이상 수집되어야 함)
- **시간 소요:** 1KB 청크 10개를 받는 데 5초가 걸림 (약 16kbps 수준의 극도로 낮은 처리량).

---

## 2. 주요 원인 분석 (Root Causes)

### **A. DB I/O 동기화 지연 (가장 유력한 원인)**
- **문제:** `drone_master.py`는 `DATA` 패킷을 받을 때마다 `db.save_fragment()`를 호출합니다. SQLite의 기본 설정은 데이터 무결성을 위해 매 쓰기마다 디스크 동기화(fsync)를 수행합니다.
- **결과:** 라즈베리 파이와 같은 SD 카드 기반 환경에서 디스크 쓰기 지연(약 100~200ms)이 발생하면, 마스터가 UDP 버퍼를 비우는 속도보다 패킷이 들어오는 속도가 빨라져 패킷 유실이 발생하고 메인 루프가 블로킹됩니다.

### **B. GRANT 재시도 로직의 설계 미비**
- **문제:** 현재 코드에서 `DATA`를 수신하면 `retry_count`는 초기화되지만, `last_grant_time`은 업데이트되지 않습니다.
- **결과:** DB 쓰기 지연으로 인해 메인 루프 한 바퀴가 1초를 넘어가면, 마스터는 데이터를 정상적으로 받고 있음에도 불구하고 `now - last_grant_time > 1.0` 조건을 만족하여 불필요한 `GRANT`를 계속 보냅니다. 이는 센서 노드의 전송 흐름을 방해합니다.

### **C. 단일 패킷 처리 구조**
- **문제:** 한 루프에 `sock.recvfrom()`을 한 번만 호출합니다.
- **결과:** 대량의 데이터가 버퍼에 쌓여있어도 하나씩 처리하고 DB에 기록하느라 전체적인 처리 속도가 데이터 송신 속도를 따라가지 못합니다.

---

## 3. 해결 방안 (Optimization Strategies)

### **Step 1: DB 성능 최적화 (Immediate Fix)**
`db_manager.py` 내의 SQLite 연결 설정에 비동기 모드를 도입하여 쓰기 속도를 극대화합니다.
```python
# db_manager.py 추천 설정
self.conn.execute("PRAGMA synchronous = OFF")
self.conn.execute("PRAGMA journal_mode = WAL")
```

### **Step 2: 마스터 루프 및 재시도 로직 개선**
데이터 수신 시 `last_grant_time`을 갱신하여 불필요한 재전송을 방지하고, 한 루프에서 여러 개의 패킷을 처리하도록 수정합니다.
```python
# drone_master.py 수정 제안
while True:
    # 1. 버퍼가 빌 때까지 모든 패킷 처리 (Non-blocking 방식)
    while True:
        try:
            data, addr = sock.recvfrom(2048)
            # 패킷 처리 로직...
            if msg_type == "DATA":
                sensors_mem[s_id]['last_grant_time'] = time.time() # 시간 갱신
        except socket.error:
            break # 버퍼 비었음
```

### **Step 3: 슬롯 종료 조건 강화**
데이터가 들어오지 않는데 슬롯을 5초간 유지하는 것은 비효율적입니다. 데이터 수신 간격이 일정 시간(예: 0.5초) 이상 벌어지면 즉시 슬롯을 종료하도록 `idle_timeout`을 도입합니다.

---

## 4. 기대 효과
- **처리량 향상:** DB 병목 해소 시 초당 수백 개의 청크 처리 가능 (수 Mbps 대역폭 확보).
- **안정성:** 불필요한 `GRANT` 재전송이 사라져 센서-마스터 간의 프로토콜 오버헤드 감소.
- **배터리 효율:** 수집 시간이 단축되어 드론 및 센서 노드의 배터리 소모 최적화.
