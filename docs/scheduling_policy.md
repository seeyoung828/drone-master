# 스케줄링 정책 문서

## 1. 문서 목적

본 문서는 Raspberry Pi AP가 드론 역할을 수행하며 여러 개의 고정된 ESP 모듈과 순차적으로 통신하여 데이터를 수집하는 환경에서, 각 ESP와의 통신 기회를 공정하게 분배하기 위한 스케줄링 정책을 정의한다.

본 정책의 목적은 다음과 같다.

1. 특정 ESP가 지나치게 오랜 시간 통신을 점유하지 않도록 한다.
2. 한 번의 접촉에서 전송이 끝나지 않더라도 이후 재접촉 시 이어받을 수 있도록 한다.
3. 모든 ESP가 일정 수준 이상의 통신 기회를 얻도록 한다.
4. 구현이 단순하고 실험 및 디버깅이 쉬운 구조를 제공한다.

---

## 2. 문제 정의

본 프로젝트에서는 여러 개의 ESP 모듈이 고정된 위치에 배치되어 있고, Raspberry Pi가 이동하면서 각 ESP와 짧은 시간 동안 통신하여 데이터를 수집한다.

이때 다음과 같은 문제가 발생할 수 있다.

- ESP마다 보유 데이터 양이 다르다.
- Raspberry Pi와 ESP의 접촉 시간은 제한적이다.
- 데이터가 많은 ESP 하나가 너무 오래 전송하면 다른 ESP의 수집 기회가 줄어든다.
- 반대로 너무 짧게 끊으면 전체 수집 완료 시간이 지나치게 늘어난다.
- 한 번의 접촉에서 모든 데이터를 다 전송하지 못하는 경우가 자주 발생한다.

따라서 본 프로젝트에서는 공정성, 부분 전송 허용, 재접촉 기반 복원 가능성을 동시에 고려한 스케줄링 정책이 필요하다.

---

## 3. 설계 목표

### 3.1 공정성 보장
각 ESP는 다른 노드에 의해 지속적으로 밀려나지 않고 통신 기회를 얻어야 한다.

### 3.2 과도한 점유 방지
하나의 ESP가 지나치게 오랜 시간 통신을 점유하지 않도록 해야 한다.

### 3.3 부분 전송 지원
한 번의 접촉 동안 데이터를 일부만 받더라도, 이후 다시 접촉했을 때 이어받기가 가능해야 한다.

### 3.4 구현 단순성
학생 프로젝트 수준에서 실제 구현 가능한 수준이어야 하며, Raspberry Pi와 ESP 모두에서 무리 없이 처리할 수 있어야 한다.

---

## 4. 기본 스케줄링 정책

## 4.1 정책 이름
슬롯 기반 하이브리드 스케줄링 정책

## 4.2 정책 개요
각 ESP와의 통신은 하나의 전송 슬롯(slot) 으로 관리한다.

Raspberry Pi는 한 ESP와 통신할 때 다음 두 개의 상한을 동시에 둔다.

- 최대 통신 시간 T
- 최대 전송 청크 수 N

다음 중 하나를 먼저 만족하면 현재 ESP와의 슬롯을 종료한다.

- 누적 통신 시간이 T 이상이 됨
- 수신한 청크 수가 N 이상이 됨
- 전체 데이터 전송이 완료됨
- 링크 상태가 악화되어 더 이상 안정적인 통신이 어렵다고 판단됨

즉, 한 ESP가 한 번의 접촉에서 무한정 데이터를 보내는 것을 방지하면서도, 너무 적은 양만 받고 끝나는 문제도 줄일 수 있도록 설계한다.

---

## 5. 정책 선택 이유

### 5.1 시간 제한만 둘 경우
최대 통신 시간만 제한하면 링크 상태가 좋을 때도 일정 시간에 도달하면 무조건 끊기게 된다. 반대로 링크 상태가 나쁠 경우 거의 데이터를 받지 못했는데도 시간이 끝나 종료될 수 있다.

### 5.2 청크 수 제한만 둘 경우
최대 청크 수만 제한하면 통신 상태가 불안정할 때 소량의 데이터를 받는 데도 지나치게 긴 시간이 소요될 수 있다. 이 경우 특정 ESP가 오랜 시간 채널을 점유하게 된다.

### 5.3 하이브리드 제한의 장점
시간과 청크 수를 동시에 제한하면 위 두 문제를 동시에 줄일 수 있다. 따라서 본 프로젝트에서는 하이브리드 방식이 가장 적절하다.

---

## 6. 기본 규칙

### 6.1 전송 단위
모든 데이터는 청크 단위로 나누어 전송한다.  
각 청크는 0부터 시작하는 정수 인덱스를 가진다.

예:
- 0
- 1
- 2
- ...
- total_chunks - 1

### 6.2 통신 시작
Raspberry Pi는 ESP와 연결되면 먼저 해당 ESP의 다음 정보를 확인한다.

- node_id
- data_id
- total_chunks
- remaining_chunks (선택)

그 후 로컬 세션 정보에서 마지막으로 수신 완료한 청크 번호를 조회하여 어디서부터 이어받을지 결정한다.

### 6.3 슬롯 내 통신
ESP는 Raspberry Pi가 요청한 시작 청크부터 순차적으로 청크를 전송한다.  
Raspberry Pi는 청크를 정상 수신하면 ACK를 보내고, 마지막 수신 청크 정보를 즉시 저장한다.

### 6.4 슬롯 종료
다음 중 하나를 만족하면 Raspberry Pi는 현재 ESP와의 통신을 종료한다.

- 최대 시간 T 도달
- 최대 청크 수 N 도달
- 전체 데이터 수신 완료
- 링크 오류 또는 타임아웃 발생

### 6.5 다음 ESP로 전환
현재 ESP 슬롯이 종료되면 Raspberry Pi는 종료 사유를 기록하고 다음 ESP로 전환한다.  
이때 현재 ESP의 전송 상태는 실패가 아니라 일시 중단(PAUSED) 으로 간주한다.

---

## 7. 공정성 규칙

### 7.1 기본 원칙
Raspberry Pi는 특정 ESP와의 슬롯이 종료되면, 아직 전송이 완료되지 않았더라도 다른 ESP에게 기회를 부여해야 한다.

### 7.2 연속 점유 제한
가능하면 동일 ESP와 연속으로 여러 슬롯을 수행하지 않는다.  
단, 다른 접촉 가능한 ESP가 전혀 없는 경우에는 예외적으로 연속 슬롯을 허용할 수 있다.

### 7.3 장기 미접촉 노드 고려
오랫동안 접촉하지 못한 ESP는 다음 탐색 시 우선적으로 처리할 수 있다.  
초기 버전에서는 필수 규칙으로 두지 않고, 확장 규칙으로 남긴다.

---

## 8. 권장 초기 파라미터

초기 실험에서는 다음 값을 권장한다.

- 청크 크기: 256B
- 최대 슬롯 시간 T: 4초
- 최대 청크 수 N: 12
- ACK 방식: 청크마다 1회
- 청크 재전송 횟수: 최대 3회

이 값은 실험 후 조정 가능하다.

---

## 9. 세션 복원과의 연계

본 정책은 중간 중단을 허용하는 대신 반드시 세션 복원이 가능해야 한다.

Raspberry Pi는 각 ESP에 대해 최소한 다음 정보를 저장해야 한다.

- node_id
- data_id
- total_chunks
- last_received_chunk
- last_contact_time
- session_state
- completed 여부

재접촉 시 Raspberry Pi는 `last_received_chunk + 1`부터 다시 요청한다.

예:
- 직전 접촉에서 0번부터 23번까지 수신 완료
- 다음 접촉에서는 24번부터 요청

---

## 10. 종료 사유 정의

슬롯 종료 시 종료 원인은 반드시 기록해야 한다.

종료 사유 예시는 다음과 같다.

- `completed`: 전체 데이터 전송 완료
- `time_limit`: 최대 시간 도달
- `chunk_limit`: 최대 청크 수 도달
- `link_loss`: 링크 단절 또는 품질 저하
- `timeout`: 응답 지연
- `manual_stop`: 수동 종료
- `error`: 내부 오류

---

## 11. 예외 상황 처리

### 11.1 ACK 유실
ESP가 청크를 전송했으나 ACK를 받지 못하면 해당 청크를 최대 3회까지 재전송한다.

### 11.2 연결 중간 단절
연결이 갑자기 끊긴 경우, 마지막으로 ACK된 청크까지만 정상 수신으로 인정한다.

### 11.3 ESP 재부팅
ESP가 재부팅되어 내부 상태를 잃더라도, Raspberry Pi의 세션 정보가 기준이 되도록 한다.

### 11.4 Raspberry Pi 재부팅
Raspberry Pi도 재부팅 후 세션 정보를 로컬 DB에서 불러와 이어받을 수 있어야 한다.

### 11.5 데이터 변경
동일 node_id에서 이전과 다른 data_id 또는 total_chunks가 보고되면 새로운 데이터 세션으로 간주한다.

---

## 12. 평가 항목

정책의 성능을 평가하기 위해 다음 항목을 측정한다.

- ESP별 평균 대기 시간
- 전체 데이터 수집 완료율
- 한 슬롯당 평균 수신 청크 수
- 세션 복원 성공률
- 전체 수집 완료까지 걸린 총 시간
- 특정 ESP의 최대 연속 점유 시간

---

## 13. 최종 요약

본 프로젝트에서는 Raspberry Pi가 여러 ESP와 순차적으로 접촉하며 데이터를 수집하므로, 특정 ESP의 과도한 점유를 방지하면서도 미완료 데이터는 이후 접촉에서 이어받을 수 있어야 한다.

이를 위해 본 문서는 각 ESP와의 통신을 전송 슬롯으로 나누고, 최대 시간 T와 최대 청크 수 N을 동시에 제한하는 슬롯 기반 하이브리드 스케줄링 정책을 제안한다.

이 정책은 공정성, 구현 단순성, 세션 복원 가능성을 동시에 만족하는 기본 정책으로 사용한다.
