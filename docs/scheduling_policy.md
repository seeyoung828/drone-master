# 🛰️ 드론 기반 데이터 수집 스케줄링 정책 (v2.2)

---

## 1. 문서 목적

본 문서는 드론(Raspberry Pi AP)이 이동하며 고정된 여러 센서 노드(ESP32-CAM)로부터 이미지 데이터를 효율적으로 수집하기 위한 **하이브리드 공정성 스케줄링(Hybrid Fairness Scheduling)** 정책을 정의한다.

특히 드론의 **배터리 보존(Energy-Efficient Collection)**과 **데이터 수집의 공정성(Fairness)**을 보장하여 단일 노드의 네트워크 독점(Monopoly)을 방지하고 전체 수집 효율을 극대화하는 것을 목표로 한다.

---

## 2. 문제 정의 및 설계 목표

- **제한된 접촉 시간**  
  드론의 이동 속도로 인해 노드와의 통신 가능 시간은 매우 짧다.

- **공정성 및 에너지 효율성**  
  드론의 배터리 제약 조건을 고려하여 불필요한 대기 전력을 최소화(Energy-Efficient)하고, 특정 노드의 데이터 독점(Traffic Congestion)을 방지하면서 신호 상태가 좋을 때 최대한 많은 데이터를 수집해야 한다. (Round-Robin + RSSI 가중치 결합)

- **세션 연속성**  
  통신 단절 후 재접촉 시 이전 전송 지점부터 즉시 재개할 수 있어야 한다.

---

## 3. 타겟 선택 정책 (Selection Policy)

드론은 BEACON 정보를 기반으로 다음 전송 권한(GRANT)을 부여할 노드를 결정한다.

가장 높은 **스케줄링 점수(Score)**를 가진 노드를 선택한다.

### 3.1 스케줄링 점수 공식

$$
Score = (w_1 \times NormRSSI) + (w_2 \times NormRemaining) + (w_3 \times NormAging)
$$

#### 구성 요소

- **NormRSSI (신호 품질)**
  - RSSI 값 (-100 ~ -30 dBm)을 0 ~ 1로 정규화
  - 신호가 좋을수록 높은 점수

- **NormRemaining (데이터 시급성)**
  - 남은 청크 비율을 0 ~ 1로 정규화
  - 데이터가 많이 남을수록 높은 점수

- **NormAging (미접촉 시간)**
  - 미접촉 시간($T_{now} - T_{last\_contact}$)을 기반으로 하며, 60초 도달 시 1.0으로 정규화.
  - $\min(1.0, (T_{now} - T_{last\_contact}) / 60)$

---

### 3.2 권장 가중치

| 항목              | 값  |
| ----------------- | --- |
| $w_1$ (RSSI)      | 0.3 |
| $w_2$ (Remaining) | 0.4 |
| $w_3$ (Aging)     | 0.3 |

## 4. 데이터 저장 및 무결성 정책

드론은 각 노드의 Data_ID별 max_idx를 SQLite에 저장하며, 재접촉 시 이를 GRANT의 Start_Idx로 사용한다

1. 파일 포맷
   - 본 프로젝트는 JPG 파일만을 취급하며, 파일명은 Data_ID를 사용

2. 임시 저장 (.tmp)
   - 수집 중인 데이터는 최종 검증 전까지 Data_ID.tmp 확장자로 저장하여 미완성 파일과 구분

3. 무결성 검증
   - 전체 청크 수집 완료 후, Slave가 보낸 COMPLETE 메시지의 CRC32 값과 Master가 직접 계산한 .tmp 파일의 CRC32 값을 대조

4. 최종 전환 (.jpg)
   - 체크섬이 일치할 경우에만 확장자를 .jpg로 변경하고 수집 완료(COMPLETED) 처리

5. 실패 처리
   - 체크섬 불일치 시 해당 .tmp 파일을 삭제하고 해당 Data_ID 세션을 초기화(재수집)
   - 수집 중 동일 노드에서 `Data_ID`가 변경되거나 `Total_Chunks`가 달라지면, 드론은 즉시 해당 노드의 기존 `.tmp` 파일을 삭제(Purge)하고 0번 인덱스부터 재수집한다.

## 5. 하이브리드 슬롯 종료 정책 (Termination Policy)

드론의 배터리 보존과 공정성을 위해 다음 조건 중 하나라도 만족하면 즉시 전송 권한을 **회수(Revoke)**하고 슬롯을 종료한다:

- **최대 점유 시간 제한 (Max Occupancy Time, $T$)**
  - 슬롯 시작 후 누적 통신 시간이 설정된 $T$초를 초과한 경우.

- **최대 처리 데이터량 제한 (Max Throughput, $N$)**
  - 한 슬롯에서 수신한 데이터 청크 수가 $N$개를 초과한 경우.

- **신호 품질 저하 (Preemptive Revoke, v3.8)**
  - RSSI가 즉시 회수 임계치($-85$dBm) 이하로 떨어지면 남은 슬롯 시간과 관계없이 즉시 권한을 회수하고 5초간 재선택을 방지한다.

- **진행 중단 감지 (Livelock Prevent, v3.8)**
  - 동일한 인덱스가 30회 이상 연속 중복 수신될 경우, 네트워크 정체 또는 노드 오류로 간주하고 즉시 세션을 중단한다.

- **전송 완료**
  - 해당 노드의 모든 데이터 조각을 성공적으로 수신한 경우.

## 6. 기회주의적 동적 파라미터 (Dynamic Thresholds)

통신 환경 및 드론의 상태(배터리 잔량, 노드 수)에 따라 전송 효율을 극대화하기 위해 임계치를 동적으로 조정할 수 있다.

| 환경      | 조건                 | 정책 (Max Throughput $N$) |
| --------- | -------------------- | ------------------------- |
| 최적 환경 | RSSI > -50 dBm       | $N = 40$                  |
| 일반 환경 | -50 ≥ RSSI > -75 dBm | $N = 20$                  |
| 한계 환경 | RSSI ≤ -75 dBm       | $N = 10$                  |

## 7. 통신 규격 및 데이터 무결성

### 7.1 패킷 구조 (v3.0 수정)

`[Type]|[S_ID]|[Data_ID]|[Total_Chunks]|[Current_Idx]|[Last_Flag]|[Payload]`

- 파이프(`|`) 구분자 기반

| 필드명 | 설명 | 예시 |
| :--- | :--- | :--- |
| **Type** | 패킷 종류 (BEACON, GRANT, DATA) | DATA |
| **S_ID** | 센서 노드의 고유 식별자 | Sensor_01 |
| **Data_ID** | 현재 전송 중인 이미지 세션 ID | 04123045 |
| **Total_Chunks** | 전체 데이터 청크 개수 | 100 |
| **Idx** | 현재 전송 중인 청크의 인덱스 | 45 |
| **Last_Flag** | 마지막 조각 여부 (0: 중간, 1: 마지막) | 0 |
| **Payload** | 실제 바이너리 데이터 (DATA 타입에만 존재) | [Binary Data] |

> **중요 (v3.0):** 노드 전송 지연 방지를 위해 노드는 더 이상 RSSI를 측정하여 보내지 않는다. 드론(Master)이 `iw station dump` 등을 활용하여 수신 시점의 신호 강도를 직접 측정하여 스케줄링에 활용한다.

---

### 7.2 신뢰성 및 무결성

- **Block ACK**
  - 드론이 보내는 GRANT 패킷의 시작 인덱스 번호가 이전 청크들에 대한 암시적 ACK 역할을 수행한다.

- **에러 복구**
  - GRANT 송신 후 0.3초 이내에 데이터가 오지 않을 경우 최대 3회까지 재시도하며, 이후에는 해당 노드를 TIMEOUT 상태로 변경하고 다음 노드로 이동한다.

- **최종 검증**
  - 각 이미지 파일의 수집이 완료되면 전체 데이터에 대해 Checksum(CRC32)을 수행하여 데이터 오염 여부를 확인한다.

## 8. 권장 파라미터

---

- 청크 크기 (Chunk Size): 1024 Bytes (1KB)
- 최대 슬롯 시간 ($T$): 5초
- 기본 최대 청크 수 ($N$): 20개
- 비콘 주기 (Beacon Interval): 0.1초
- 스케줄러 타임아웃: 0.3초

## 9. 상태 정의

| 상태       | 설명                                                  |
| ---------- | ----------------------------------------------------- |
| IDLE       | 아직 수집이 시작되지 않았거나 비콘만 감지된 초기 상태 |
| COLLECTING | 데이터 전송 중                                        |
