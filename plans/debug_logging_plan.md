# 🛠️ 드론 마스터 정밀 로깅 및 원인 분석 계획 (Debug Plan)

## 1. 목적
- `drone_master.py`와 `sensor_node.py` 간의 통신 시퀀스를 실시간으로 추적하여, 노드에서 `Test1 error`가 발생하는 정확한 원인(어떤 메시지가 수신되는지)을 파악하고 마스터의 의사결정 과정을 가시화함.

## 2. 주요 로깅 포인트 (수정 계획)

### 2.1 패킷 수신부 (Incoming Traffic)
- **모든 패킷**: 수신되는 모든 패킷의 `Type`, `S_ID`, `Data_ID`, `Idx`를 출력하여 마스터가 무엇을 보고 있는지 확인.
- **BEACON**: 세션 상태(신규/기존/완료)에 따른 판정 결과 로그 활성화.
- **DATA**: 수신된 청크의 인덱스를 출력하여 데이터 유입 확인.

### 2.2 패킷 송신부 (Outgoing Traffic)
- **GRANT**: 어떤 노드에게 몇 번 인덱스부터 몇 개를 요청하는지 명시적 출력.
- **COMPLETE_ACK**: 중복 수집 방지(Early Exit)로 인해 ACK가 나가는 경우 로그 출력.
- **ERROR/REVOKE**: 전송되는 모든 제어 메시지와 그 사유를 출력.

### 2.3 스케줄링 로직 (Internal Logic)
- **타겟 선정**: 점수 계산 결과와 현재 선정된 타겟(`current_target`)을 주기적으로 노출.
- **타임아웃/재전송**: GRANT 재전송 시점과 슬롯 종료 사유를 명확히 기록.

## 3. 구현 세부 사항
- `dprint` 함수를 사용하여 즉각적인 `stdout.flush()`를 보장함으로써 로그가 밀리지 않도록 함.
- 로그 포맷을 일관되게 유지하여 분석 효율 증대.

## 4. 작업 절차
1.  `drone_master.py`의 각 주요 분기점에 로깅 구문 삽입.
2.  사용자 승인 후 코드 적용.
3.  실행 후 출력되는 로그를 분석하여 `sensor_node.py`의 `Test1 error`가 발생하는 지점의 마스터 상태 확인.
