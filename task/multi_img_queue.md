# 📂 다중 이미지 큐(Multi-Image Queue) 구현 설계서

본 문서는 센서 노드(ESP32-CAM)에 저장된 여러 장의 이미지를 순차적으로 드론에게 전송하기 위한 큐잉 시스템의 상세 구현 절차를 정의한다.

---

## 1. 개요 (Overview)

현재 시스템은 `test.jpg` 단일 파일만을 대상으로 수집을 수행한다. 현장 적용 시 센서 노드는 주기적으로 촬영된 여러 장의 이미지를 보유하게 되며, 드론은 한 번의 비행(또는 여러 번의 접촉)을 통해 이 이미지들을 순차적으로 모두 수집해야 한다.

---

## 2. 주요 수정 요구사항

### 2.1 센서 노드 (sensor_node.py)
- **디렉토리 모니터링**: 특정 폴더(`images/`) 내의 모든 `.jpg` 파일을 검색하여 큐에 등록.
- **이미지 식별자 관리**: 파일의 생성 시간 또는 파일명을 기반으로 고유한 `Data_ID` 부여.
- **상태 전이 로직**: 한 이미지의 전송 및 `COMPLETE` 보고가 완료되면 다음 이미지로 자동 전환.

### 2.2 드론 마스터 및 DB (drone_master.py, db_manager.py)
- **세션 연속성 유지**: 동일 센서(`S_ID`)로부터 새로운 `Data_ID` 비콘 수신 시, 이전 이미지가 완료되었다면 자연스럽게 신규 세션 생성.
- **Purge 정책 완화**: (선택 사항) 미완료된 이전 세션을 유지할 것인지, 아니면 현재처럼 최신 데이터 위주로 관리할 것인지 결정.

---

## 3. 상세 구현 절차

### 1단계: 센서 노드 이미지 큐 관리 도입
- `SensorNode` 클래스 수정:
    - `self.image_queue`: 전송 대기 중인 파일 경로 리스트.
    - `self.current_image_path`: 현재 전송 중인 파일.
    - `_scan_images()`: 초기화 시 및 주기적으로 디렉토리를 스캔하여 신규 파일을 큐에 추가하는 메서드.
- `Data_ID` 생성 로직 변경:
    - 현재: 실행 시점 시간(`strftime`)
    - 변경: 파일의 수정 시간(mtime) 또는 파일명에서 추출하여 파일마다 고유하게 유지.

### 2단계: 파일 전송 루프 고도화
- `run()` 메서드의 메인 루프를 이중 구조로 변경:
    - **Outer Loop**: 큐에서 다음 이미지를 꺼내어 세션 초기화.
    - **Inner Loop**: 현재 이미지의 모든 조각을 `GRANT`에 따라 전송 (기존 `while True` 로직).
- `COMPLETE` 송신 후 처리:
    - `COMPLETE` 패킷을 전송한 후, 마스터가 더 이상 해당 `Data_ID`에 대해 `GRANT`를 보내지 않는지(또는 일정 시간 대기) 확인 후 Outer Loop로 복귀하여 다음 이미지로 전환.

### 3단계: 드론 마스터 세션 전환 로직 최적화
- `db_manager.py`의 `prepare_session` 수정:
    - 현재는 `S_ID`가 같고 `Data_ID`가 다르면 기존 데이터를 무조건 `DELETE`함.
    - **변경**: 이전 `Data_ID` 세션의 상태가 `COMPLETED`라면 삭제하지 않고 보존하거나, 로그로 남긴 후 신규 세션을 생성하도록 수정.
- `drone_master.py`의 `BEACON` 처리:
    - 동일 노드에서 새로운 `Data_ID`가 오면 `prepared_sessions` 캐시를 갱신하고 스케줄링 점수를 다시 계산.

### 4단계: 전송 완료 확정 메커니즘 (Master → Slave ACK)
- (선택 사항) 현재 프로토콜에는 마스터가 검증 완료 후 슬레이브에게 주는 확정 패킷이 없음.
- 슬레이브가 다음 이미지로 넘어가기 전, 마스터로부터 해당 `Data_ID`에 대한 `VERIFIED` 메시지를 받도록 프로토콜 확장 고려 (또는 타임아웃 기반 전환).

---

## 4. 데이터 구조 및 흐름 (Flow)

1.  **[Slave]** `images/` 폴더 스캔 → `[img1.jpg, img2.jpg]` 큐 생성.
2.  **[Slave]** `img1.jpg`에 대한 `BEACON` 송신.
3.  **[Master]** `img1.jpg` 수집 및 검증 완료 → `COMPLETED` 상태 저장.
4.  **[Slave]** `COMPLETE` 송신 후 일정 시간 `GRANT`가 없으면 `img1.jpg`를 전송 완료 폴더로 이동.
5.  **[Slave]** 차순위 `img2.jpg`에 대한 `BEACON` 송신 시작.
6.  **[Master]** 새로운 `Data_ID` 감지 후 신규 세션으로 인식하여 수집 재개.

---

## 5. 예외 상황 처리

- **수집 중단 후 재연결**: 드론이 멀어졌다가 다시 올 때, 슬레이브는 큐의 '현재 전송 중이었던 이미지'부터 다시 비콘을 보내야 함 (상태 보존 필요).
- **중복 이미지**: 동일한 내용의 이미지가 생성될 경우를 대비해 파일 해시 또는 정밀한 타임스탬프를 `Data_ID`로 사용.
- **이미지 유실**: 드론이 `COMPLETE`를 받지 못한 상태에서 슬레이브가 다음 이미지로 넘어가면 안 됨. (슬레이브는 마스터의 반응을 최소 1초 이상 모니터링해야 함)

---

## 6. 구현 우선순위

1.  **High**: `sensor_node.py` 내의 파일 리스트 스캔 및 순차 `run()` 루프 구현.
2.  **Medium**: 파일별 고유 `Data_ID` 매핑 (mtime 기반).
3.  **Low**: 마스터의 검증 성공 여부를 슬레이브에게 피드백하는 전용 메시지 추가.
