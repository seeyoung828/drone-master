# 📋 시스템 라이브락(Livelock) 및 무한 스케줄링 루프 분석 보고서

본 문서는 `error.txt`에서 발생한 ESP32-CAM의 송신 타임아웃 에러와 라즈베리파이(드론 마스터)가 특정 노드를 무한히 스케줄링하는 현상에 대한 원인을 분석하고 해결 방안을 제시한다.

---

## 1. 에러 현상 요약

1.  **ESP (Slave):** `[Network Error] Beacon/Data chunk send failed: timed out` 메시지가 반복되며 소켓 송신 버퍼 오버플로우 발생.
2.  **Pi (Master):** 특정 노드(`Sensor_02`)에 대해 `[Slot End] ... Chunks: 20`이 매우 짧은 간격(0.2s)으로 무한 반복 출력됨.
3.  **특이 사항:** ESP를 강제 종료해야만 마스터가 다른 노드(`Sensor_01`)의 재시도(Retry) 및 타임아웃 처리를 시작함. 이는 `Sensor_02`가 마스터의 스케줄링 자원을 독점하고 있었음을 의미함.

---

## 2. 근본 원인 분석 (Root Cause Analysis)

### 2.1 스케줄링 점수 계산의 허점 (Aging Bug)
`drone_master.py`의 `calculate_score` 함수는 `last_seen`을 기반으로 `Aging` 점수를 계산한다. 그러나 현재 코드는 **`BEACON` 수신 시에만 `last_seen`을 업데이트**하고 있다.
- **문제:** `DATA` 패킷을 대량으로 보내는 동안 `BEACON`이 수신되지 않으면, 해당 노드는 활발히 데이터를 보내고 있음에도 불구하고 마스터는 이 노드가 오랫동안 대기(Aging)했다고 판단하여 점수를 계속 높게 유지한다.
- **결과:** 슬롯이 종료되자마자 다시 가장 높은 점수를 얻어 즉시 재선택되는 '스케줄링 라이브락'이 발생한다.

### 2.2 네트워크 혼잡 및 소켓 버퍼 관리 실패
ESP32-CAM은 `send_data_chunks`에서 0.005초 간격으로 패킷을 송신한다.
- **문제:** 마스터가 스케줄링 루프에 빠져 `GRANT`를 과도하게 빠르게 보내면, ESP는 처리 능력 이상의 데이터를 송신하려고 시도하게 된다.
- **결과:** OS 레벨의 송신 버퍼가 가득 차면서 `sendto` 호출이 타임아웃되고, ESP의 `run()` 루프는 에러 상태를 복구하지 못한 채 계속 송신을 시도하게 된다.

### 2.3 슬롯 종료 후 '냉각기(Cool-down)' 부재
현재 마스터는 슬롯이 종료되면 즉시 전체 노드 중 점수가 가장 높은 노드를 다음 타겟으로 선정한다.
- **문제:** 직전 슬롯을 사용한 노드가 여전히 높은 점수를 가지고 있다면, 다른 노드에게 기회가 돌아가기 전에 즉시 다시 선택된다.
- **결과:** `error.txt`의 `Time: 0.2s` 로그처럼 비정상적으로 짧은 간격으로 동일 노드가 반복 선택된다.

---

## 3. 해결 방안 (Detailed Solutions)

### 3.1 마스터: 데이터 수신 시 Aging 초기화 (Fix 1)
`DATA` 패킷을 수신했을 때도 `last_seen`을 업데이트하여, 현재 데이터를 보내고 있는 노드의 Aging 점수를 0으로 유지한다.

```python
# drone_master.py 수정 예시
elif msg_type == "DATA":
    if s_id in sensors_mem:
        sensors_mem[s_id]['last_seen'] = time.time()  # Aging 점수 초기화
        # ... 기존 로직
```

### 3.2 마스터: 직전 노드 페널티 제도 도입 (Fix 2)
방금 슬롯 점유를 마친 노드에게 일시적인 페널티를 부여하거나, 스케줄링 시 강제로 일정 시간(예: 1초) 동안 Aging 점수를 0으로 처리하여 라운드 로빈(Round-Robin) 효과를 유도한다.

### 3.3 슬레이브: 송신 에러 시 지수 백오프(Exponential Back-off) 적용 (Fix 3)
`sendto` 에러 발생 시 단순 `break`가 아니라, 소켓 상태를 점검하고 점진적으로 대기 시간을 늘려 네트워크 혼잡을 완화한다.

```python
# sensor_node.py 수정 예시
try:
    self.sock.sendto(packet, (DRONE_IP, DRONE_PORT))
except socket.timeout:
    print("[Network Error] Buffer full, backing off...")
    time.sleep(0.1) # 대기 후 재시도 또는 루프 탈출
```

### 3.4 전송 종료 확정(ACK) 프로토콜 강화 (Fix 4)
슬레이브가 `COMPLETE`를 보낸 후 마스터로부터 명시적인 `ACK` 또는 `GRANT(Next_ID)`를 받기 전까지는 송신 버퍼를 비우고 대기하는 로직을 추가하여 마스터와 상태를 동기화한다.

---

## 4. 결론

이번 장애는 **"활동 중인 노드의 Aging 점수가 초기화되지 않는 버그"**와 **"너무 빠른 재스케줄링"**이 결합되어 발생한 현상이다. 마스터의 점수 계산 로직을 정교화하고, 네트워크 혼잡 시 슬레이브가 능동적으로 송신 속도를 조절하는 메커니즘을 도입함으로써 무한 루프 문제를 근본적으로 해결할 수 있다.
